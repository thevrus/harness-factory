# Protected paths: changes here need a human (CODEOWNER) approval.
#
# Syntax is gitignore-style, one pattern per line:
#   name        matches a file or directory with that name at any depth
#   dir/        matches a directory (and everything inside it) at any depth
#   a/b/**      matches everything under a/b (anchored at the repo root)
#   /file       anchored at the repo root
#   !pattern    re-includes a path an earlier line matched
# Matching is case-insensitive on purpose: on a case-insensitive filesystem
# ".GitHub/workflows" is the same directory as ".github/workflows".
#
# Who reads this file:
#   .harness/hooks/protect-paths.sh   makes the agent's file-edit tools ask a
#                                     human first (.harness/acceptance/ is
#                                     always blocked)
#   .harness/bin/diff-guard.sh        fails CI when a diff touches a match
# Both also apply a built-in copy of the defaults below, so deleting a default
# from this file does not unprotect it.
#

# `human_only_areas` in .harness/config.json land in the block between the
# "harness:config" marker lines, written by `hf_install.py sync`; do not edit
# inside that block.
